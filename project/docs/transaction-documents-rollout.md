# Transaction documents

Customers can find purchase invoices and verified receipts in **Dashboard → Receipts & invoices**. Shops can open sales invoices and linked receipts from **Vendor Dashboard → Orders**. Account invoices (such as subscription invoices) remain linked from **Vendor Dashboard → Invoices**. The built-in print dialog can save a PDF where the browser supports that option.

An order invoice is a numbered view of the recorded order, not a tax invoice or proof of payment. A receipt uses the receipt number generated by the trusted payment flow, with the linked payment, amount and currency checked. Cash-on-delivery and completed orders do not count as proof of payment. Test payments are excluded. Refund status is displayed against the original amount; the document does not calculate a remaining balance or issue tax credit notes.

The release changes no checkout, prices, payment providers, tax rules, or data. Migration `0207_private_transaction_documents` adds authenticated, buyer/owner-scoped read functions without widening raw table permissions. Apply and verify that migration on the intended production project before deploying the app. Only run the pgTAP fixture in an isolated database; it creates synthetic orders and payments, then rolls back.
