## Local support read-model change

Migration `20260929110000_0065_admin_support_read_models.sql` initially defined bounded support reads. It is superseded by local draft `0068`, which authorizes support reads and mutations using `is_super_admin()` or the database-assigned `can_manage_support` capability. It also narrows support-ticket/reply RLS to that capability plus ticket-owner access to their own ticket and non-internal replies. The support browser client uses RPCs; list/reply wrappers return explicit discriminated results, detail throws a sanitized error, and the UI renders retryable errors. Support export remains absent. The drafts have not been applied or live-tested.

Migration `20260929120000_0066_admin_vendor_directory.sql` adds a bounded business directory RPC for super-admin and university-admin readers. University scope is checked with `can_manage_university()` inside the function; university administrators do not receive owner email. It has matching lower-case trigram indexes for its escaped substring query. The directory is read-only for university admins, while super-admin approve/suspend UI requires a reason and uses existing protected RPCs. The old browser-side export was removed; the migration has not been applied.

The updated local draft `0064` adds trigram-indexed escaped substring search and bounded pagination. The UI debounces searches and supports next/previous pages. Search remains limited to vendors, orders, universities, and super-admin-only user matches; restricted data types remain excluded. Migration `0067` resolves the existing scoped branding/audit mismatch through a separate internal audit helper with no authenticated execute grant and a field-limited metadata RPC. The generic staff audit logger remains staff-only. Neither migration has been applied.

Draft `0068` replaces the previously direct, RLS-protected `role_permissions` browser read with a super-admin-only role-permission read RPC and a reason-required RPC that can update only three moderator capabilities. It records before/after values in the trusted audit system, does not allow `super_admin` role assignment, and requires the same `can_manage_support` permission in support route middleware, support RPCs, and RLS. Report read/resolution similarly uses `can_review_reports`, with a required bounded resolution reason. The capability update UI is intentionally not a generic role-management system. Static source tests pass, but the SQL migration has not been applied or exercised against PostgreSQL.

Draft `0069` replaces the coupon page's direct browser table operations with super-admin-only paginated reads and reasoned create/update RPCs. It revokes authenticated coupon insert/update/delete privileges and removes the old table policies; coupon redemptions and usage counters remain database-owned, and the UI retires coupons by deactivation rather than destructive deletion. It also adds a super-admin category read model so hidden categories can be listed despite public-catalog RLS, with a visible retryable error state. This is a local draft only and has not been applied or exercised against PostgreSQL.

Draft `0070` adds a bounded super-admin subscription read model and an audited, status-filtered server export capped at 5,000 records. The admin UI no longer treats a failed read as an empty result or exports only the current page from browser state. The route authenticates, checks same-origin requests, emits private/no-store CSV with formula escaping, and delegates authorization plus audit recording to the database RPC. It is a local draft only and has not been applied or exercised against PostgreSQL.

Draft `0071` removes the broad moderator payment-row RLS policy while retaining super-admin access and user-owned payment reads. It adds bounded, super-admin-only payment and invoice readers that omit webhook payloads, provider transaction references, mobile details, failure internals, and invoice billing metadata. Payment/invoice CSVs are generated server-side through resource-specific audited RPCs, status filtered, formula escaped, and limited to 5,000 records. Both screens show query failures distinctly from empty results. This is a local draft only; the migration has not been applied or exercised against PostgreSQL.

Draft `0072` adds a bounded super-admin refund queue read model and strengthens refund review so approval/rejection requires a 10–500 character decision reason, derives the actor from `auth.uid()`, and writes both financial transaction history and trusted administrative audit records. The UI now distinguishes read failure from an empty queue and removes the unsupported manual provider-reference/“process” action; provider refunds remain disabled until a trusted provider workflow exists. This is a local draft only; the migration has not been applied or exercised against PostgreSQL.

Draft `0078` and `/admin` provide university administrators a separate aggregate overview based only on active database memberships. It reports scoped student/vendor/business/catalog/order/event/support counts and scoped daily trends; it excludes payments and financial totals and does not accept a university ID from the browser. Middleware and the client shell now admit the dashboard route for university administrators, while the RPC separately rejects non-university-admin roles and users without active scope. Static tests cover source-level separation only; PostgreSQL execution and cross-university account tests remain unrun.

Draft `0079` adds a super-admin-only audit-log reader that returns at most a sanitized 500-character `reason` from metadata while withholding the raw metadata, IP address, and request context. Draft `0080` adds bounded actor ID, target ID, date-range, module, and action-search filters with supporting actor/target/time indexes; its paginated RPC remains super-admin-only. The viewer does not expose role/university/severity filters or old/new state snapshots because the current audit schema does not consistently record those fields. Both migrations are unapplied and only source-tested.

Draft `0081` adds `/admin/delivery`, a bounded read-only delivery/handoff queue. The RPC derives university access using `can_manage_university`, restricts callers to super admins and university admins, orders active handoffs first, and omits delivery addresses/instructions, buyer contact details, freeform notes, and financial fields. Existing vendor/customer transition RPCs remain the only lifecycle authority. Draft `0082` reuses the report-review capability to expose the moderation case queue and state transitions; decisions require a reason, validate allowed transitions while row-locked, add case events, and record trusted admin audit actions. Draft `0083` adds a scoped event-flag queue and reasoned dismiss/hide/approve actions, with a restricted university-admin audit helper and platform trusted audit path. These changes have static source coverage only; no staging/RLS workflow was exercised.

CMS pages/FAQ, announcements, and operational broadcasts now surface sanitized read errors with retry controls instead of displaying empty-state text after query failure. Existing content mutation RPCs are retained; CMS/announcement wrapper errors are sanitized before reaching UI. The regression assertions are static and do not exercise real RLS or browser workflows.

Draft `0084` closes the broad staff-only communication-log read path. It revokes browser SELECT on communication events, deliveries, and logs; adds super-admin or assigned `can_manage_communications` RPC reads; bounds filters/page size; computes summaries in PostgreSQL; and withholds recipient identifiers and provider references. Moderator capability changes remain super-admin-only, reason-required, and audited. `/admin/communication` consumes the narrowed RPCs, paginates, and surfaces retryable errors. It does not expose personal notification preferences, message content, delivery mutations, replay, or provider secrets. This remains un-applied/unverified against staging PostgreSQL.

Draft `0085` replaces broad staff SELECT policies on moderation case/link/event tables with a case-read, reviewer-list, assignment, and history RPC boundary. Assignment row-locks the case, validates an active super-admin or permitted moderator, rejects closed cases, requires a reason, and records both a case event and trusted admin action. The UI shows current assignee, assignment controls, and up to 100 recent case events with bounded reason text. Static checks do not substitute for executing this migration and exercising real RLS/API behavior in staging.

Draft `0086` adds aggregate-only search-quality monitoring to `/admin/search` for super-admins. Its database function bounds the reporting window and returns daily search/no-result/distinct-click counts without raw query text or session IDs. The focused admin authority suite now passes 36 tests; this migration is unapplied, and real search-event ingestion and staging PostgreSQL behavior remain unverified.
